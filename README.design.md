# Prompt List 设计理念

主要应用场景：

- 对于一个已有的角色绘画工作流，可以快捷地更换内部各种槽位 (如衣服、表情、场景)
- 可以使用多种方式修改槽位 (删除,追加原来工作流中的细节)（例如可以删除并更换旧衣服，或在旧衣服的基础上追加）
- 在原场景中添加新的角色，修改角色之间的交互

## 旧方案、代替方案

### 手动修改提示词

第一个经典的方案是修改提示词。

例如把提示词中的原衣服提示词替换掉。

- 优点
  - 简单 (重连节点即可)
- 缺点
  - 无需安装插件
  - 每次替换的时间成本高、无法快速切换
  - 无法回溯、保留历史。例如要在多套衣服中反复切换调整，切换到下套服装后可能还需要再切换回上套

### 提示词拼接

第二个经典的方案是使用提示词拼接，具体方案是使用如 `ComfyUI-KJNodes` 插件的 `Join String Multi` 节点。

然后以 "衣服前 - 衣服 - 衣服后" 的顺序将三个 "字符串节点" 连接起来。
这样当角色需要更换衣服时，更换中间节点的连接。

- 优点
  - 简单 (重连节点即可)
  - 灵活, 切换快速
- 缺点
  - 一个角色需要维护许多节点
    （例如只更换衣服，就需要维护角色的衣服前面的提示词+衣服提示词+衣服后面的提示词。
    如果要替换的槽位比较多，维护困难）
  - 区分多种槽位修改方式 (替换、追加、删除) 时需要修改连接拓扑

### 参考图节点替换

有的模型支持多参考图 (如 qwen-image-2.1)，或者通过别的方式使用参考图 (重绘、QIE、IP-Adapt 等)。

那么像更改衣服参考图，就可以完成更换衣服的需求。像姿势图参考、衣服图参考、人脸参考等，都是同理。

当然，这里更换节点有两种。一是更换图片节点，二是单个节点本身就支持切换不同的图片。

- 优点
  - 简单 (重连节点即可，在节点内更换也可)
  - 灵活, 切换快速
- 缺点
  - 通常是参考图使用，而非提示词拼接

## 新方案、Prompt List 方案

特性

- 自定义槽位
- 多种槽位编辑方式

优缺点

- 优点
  - 简单 (重连节点即可，在节点内更换也可) (节点内更换处于 TODO)
  - 灵活, 切换快速
  - 更能应对复杂场景 (如多角色拼接、多角色交互等)

## 先引 - 提示词顺序

为了更好地使用，这里有必要说一下建议的提示词使用顺序，以及如何结合使用。

(仅供参考，不同模型的表现可能略有偏差)

- 画质/画风
- 人数锚点
- 镜头/构图/角度
- 多人共享互动锚点
- **角色卡部分 (核心)**
- 背景场景/环境
- 色调/氛围/滤镜收尾

角色卡部分的细分

- 身份/名字/出处/LoRa触发词
- 头部 (脸型、发型、发饰)
- 服装
- 姿势和动作
- 持物/解除物

## UX 设计 (编辑中)

首先先设计使用场景和用户交互，这也是我设计与开发该插件的应用场景

## 应用场景 (编辑中)

### 1. 换衣服

角色卡部分

```json
[角色, 角色头部, 角色衣服 1, 角色姿势动作, ...]

变

[角色, 角色头部, 角色衣服 2, 角色姿势动作, ...]
```

### 2. 角色更换场景

```json
[画质, 人数, 镜头, 角色卡..., 场景1]

变

[画质, 人数, 镜头, 角色卡..., 场景2]
```

### 3. 角色卡与其他部分的合并

```json
这是一张角色卡的组成:

[角色1部分1, ..., 角色1部分10]

后续为了方便会简写成:

[...角色卡1]
```

> 该写法参考了 JavaScript 中的 “列表解构语法”
> 即:
> ```js
> let a, b, rest;
> [a, b] = [10, 20];
> [a, b, ...rest] = [10, 20, 30, 40, 50];
> ```

#### 角色部分与非角色部分的合并

```json
变

[画质, 人数, 镜头, ...角色卡1, 场景]
```

#### 也可以增添第二人

```json
变

[画质, 人数, 镜头, 多人共享互动, ...角色卡1, ...角色卡2, 场景]
```

### 第二人也可以是角色卡, 即角色与角色的合并

```json
[...角色卡1], [...角色卡2]

变

[画质, 人数, 镜头, 多人共享互动, ...角色卡1, 角色卡2, 场景]
```
