# Prompt List

[English](./README.md) | 简体中文

一组用于处理**提示词列表**的 ComfyUI 自定义节点。它本质上只是一个 Python `list[str]`，作为**一个值**在节点图里传递：建一次、就地改、按索引取单项、最后再拼回一条提示词。

## 列表拿来干什么 (应用场景)

列表的长度与索引的含义由你决定。这里列举作者常用的两种使用场景：

**槽位。** 给每个下标派一个固定职能，每个阶段只改动它关心的槽位：

| 下标 | 槽位 |
| --- | --- |
| 0 | 角色 / 头 |
| 1 | 服装 |
| 2 | 表情 |
| 3 | 动作 |
| 4 | 镜头 |
| 5 | 场景 |

你可以自定义他们，例如进行更细致的细分：上衣、外套、裤子、袜子、鞋子（类似于 Kisekae 插件，但自定义能力更强更灵活，你可以不关注那些你不使用的类别）

角色只描述一次，之后"换套衣服""换个镜头"就是多加一个阶段、改一两个槽位 —— 不用重抄任何文字，而且哪个阶段想验证效果，静音掉就行。[示例工作流](./examples/prompt-list-demo.json)就是这么搭的。

**提示词库。** 索引只表示"我要第几号"：把一批提示词存在画布上，用 `Get Item` 挑一条送给文本编码器。

## ComfyUI 里两种不同的"列表"

ComfyUI 本身有列表执行：输入是列表时，下游节点会逐项执行一次。本插件做的是另一件事，两者混淆是最常见的误解来源：

| | ComfyUI 列表执行 | `STRING_PYLIST`（本插件） |
| --- | --- | --- |
| 连线上传的是什么 | 每次执行传一项 | 整个数组，作为一个值 |
| 下游节点执行次数 | 每项一次 | 一次 |
| 端口类型 | 元素类型（`STRING`、`IMAGE` 等） | `STRING_PYLIST` |
| 适合 | 用同一张图批量生成 N 份 | 用槽位拼一条提示词，或者维护一个提示词库 |

`STRING_PYLIST` 是本插件定义的类型，因此只能连到本插件的节点上。里面装的就是普通的 `list[str]`。

1. 安装 [ComfyUI](https://docs.comfy.org/get_started)。
2. 推荐：安装 [ComfyUI-Manager](https://github.com/Comfy-Org/ComfyUI-Manager)，然后在其中搜索本扩展。
3. 或手动把仓库克隆到 `ComfyUI/custom_nodes`：

   ```bash
   cd ComfyUI/custom_nodes
   git clone https://github.com/LincZero/comfyui-prompt-list.git
   ```

4. 重启 ComfyUI。

所有节点都在 **Prompt List** 分类下。

## 能用它做什么

| 想做的事 | 用哪个节点 |
| --- | --- |
| 创建列表 | 下面五种创建节点任选 |
| 取其中一项 | `PromptList GetItem` |
| 看整张列表 | `PromptList Show`（JSON 预览） |

## 节点

### Create From Upstream (Auto) — `PromptList CreateFromUpstream`

把连进来的字符串收集成一张列表。每个连上的输入按端口顺序对应一项。

- 端口照常自动增减：连上最后一个会多一个，断开最后一个会收回（1–100 个）。
- 每个值都会去掉首尾空白。
- 连上但内容为空的输入保留为空项，不跳过。
- 顶上那个可选的 `prompt_list` 接上后，这些输入就变成对应项的模板（见下文「用模板修改」）。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 可选，单个端口。接上 = 下面这些字符串是这张列表的模板 |
| `text0`、`text1`、… | `STRING` | 多行文本，端口自动增减，1–100 个 |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 每个连上的端口对应一项 |
| `joined_text` | `STRING` | 上面这张列表用固定的 `,`（不带空格）拼成的整串，可直接接文本编码器 |

如果想在一步里把多张列表叠起来，见下面的 `Create From Lists (Chain)`。

### Create From Lists (Chain) — `PromptList CreateFromLists`

把几张列表当成流水线一层层叠起来：第一张列表（或你接上的 `prompt_list`）决定初始各项，后面每张都是一层模板，按端口顺序依次套用。这就是"并联转串联" —— 每一层待在各自的并联支路上，最后用这一个节点串成一条。

- 端口数量和上面的自动增长节点一致（1–100 个）。
- 一层就是一张列表：层的第 n 项改结果的第 n 项，`{{item}}` 表示保留该值，普通文字则覆盖它。
- 层比结果短时，多出来的项原样保留；层比结果长时，多出来的非空项追加到末尾。
- 某个端口接的是空列表时，这一层不改变结果。
- 输出和其他创建节点一样是两个：列表本身，以及用 `,` 拼好的整串。

接 `["111", "222"]` 和 `["{{item}}", "333"]` 时结果是 `["111", "333"]`：第一张建表，第二张保留第 0 项、替换第 1 项。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 可选，单个端口。接上 = 从这张列表开始叠，而不是从第一张输入建表 |
| `list0`、`list1`、… | `STRING_PYLIST` | 端口自动增减，1–100 个。端口顺序就是叠加顺序 |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 所有输入逐层叠加后的列表 |
| `joined_text` | `STRING` | 上面这张列表用固定的 `,`（不带空格）拼成的整串，可直接接文本编码器 |

### Create From Strings — `PromptList CreateFromStrings`

一项一个单行文本框。不接上游时是新建；接上 `prompt_list` 时，同一排文本框变成模板，按下标逐项修改那张列表。

文本框数量由 `inputcount` 控件决定（1–100，默认 2）。改完数量点一下节点上的 **Update Inputs** 按钮重建端口；加载工作流时会自动重建。

每个文本框默认是 `{{item}}`，意思是"这项不动"。每个框也可以不写字，改成接上游 `STRING`。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `inputcount` | `INT` | 1–100，默认 2。文本框数量 |
| `text_0` … `text_N-1` | `STRING` | 每项一个框，默认 `{{item}}` |
| `prompt_list` | `STRING_PYLIST` | 可选。连上 = 修改；不连/为空 = 新建 |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 新建或修改后的列表 |
| `joined_text` | `STRING` | 上面这张列表用固定的 `,`（不带空格）拼成的整串，可直接接文本编码器 |

两个输出来自同一张列表，所以 `joined_text` 就是 `",".join(prompt_list)` —— 空槽位会表现为连续两个逗号。

### Create From Strings (Multi) — `PromptList CreateFromStringsMulti`

同一个节点、同样两个输出，但文本框是多行的。适合某一项本身就是一整段话的情况。

### Create From String — `PromptList CreateFromString`

把一个多行文本框按行拆成多项，一行一项。

- 空行保留为空项，所以第 n 行永远对应第 n 项。
- 每行都会去掉首尾空白。
- 文本框为空时得到一张空列表。
- 接上 `prompt_list` 时，每一行都是模板 —— 所以一个文本框就能一次改很多项。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `text` | `STRING` | 多行文本，默认空。一行一项 |
| `prompt_list` | `STRING_PYLIST` | 可选。连上 = 修改；不连/为空 = 新建 |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 新建或修改后的列表 |
| `joined_text` | `STRING` | 上面这张列表用固定的 `,`（不带空格）拼成的整串，可直接接文本编码器 |

### Show — `PromptList Show`

输出节点，把列表以带缩进的 JSON 显示在节点上的只读框里，同时把列表原样透传，所以插在链路任何位置都行。非 ASCII 字符原样显示。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 必填 |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 原样透传的同一张列表 |

### Get Item — `PromptList GetItem`

取出某一项。索引从 0 开始。超出 `0 … 长度-1` 的索引会让本次执行报错并中止，错误里同时给出索引和列表长度；不会截断，也不会回绕。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 必填 |
| `index` | `INT` | 0–9999，默认 0。可由上游 `INT` 驱动 |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `string` | `STRING` | 取出的那一项 |

### Set Item — `PromptList SetItem`

按索引替换一项并输出修改后的列表。索引必须已经存在：本节点只替换，不追加。

它是"单点微调"工具 —— "同一张列表，但镜头换了" —— 对应的是创建节点那种"一排文本框改很多槽位"的批量操作。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 必填 |
| `index` | `INT` | 0–9999，默认 0。必须落在列表范围内 |
| `new_value` | `STRING` | 多行，替换后的内容 |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 替换了一项之后的列表副本 |

### Join To String — `PromptList JoinToString`

按列表顺序把整张列表拼成一个字符串，用分隔符（默认 `", "`）隔开。各项按原样拼接 —— 包括空项，空项会留下连续的分隔符。

每个创建节点已经自带一个 `joined_text` 输出（分隔符固定为 `,`），所以只有想换分隔符、或者列表在后面又被改过时，才需要这个节点。

**输入**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `prompt_list` | `STRING_PYLIST` | 必填 |
| `separator` | `STRING` | 单行，默认 `", "` |

**输出**

| 名称 | 类型 | 说明 |
| --- | --- | --- |
| `joined_text` | `STRING` | 拼好的一个字符串 |

## 用模板修改

五个创建节点共用同一套规则。区别只在于输入从哪来 —— 文本框（`Create From Strings` 和它的 `(Multi)`）、一个文本框的每一行（`Create From String`）、连上的字符串（`Create From Upstream`）、或者按端口顺序逐层套用的输入列表（`Create From Lists`）—— 合并方式完全一样。不接上游列表时，每个输入直接成为一项；接了上游列表时，每个输入是同一位置那一项的模板：

```text
result = list(prompt_list)                 # 没接上游时是空列表
for index, template in enumerate(boxes):
    if index < len(result):
        # {{item}} → 该项原有的内容；完全不写 {{item}} 就是覆盖该项
        result[index] = template.replace("{{item}}", result[index])
    else:
        # 文本框比列表长时，多出来的非空框追加成新项
        extra = template.replace("{{item}}", "")
        if extra.strip():
            result.append(extra)
# 文本框没有对应到的项，原样保留
```

所以"追加 / 替换 / 清空"这套说法，本质上就是你在输入里写什么：

| 想要 | 框里写 | 效果 |
| --- | --- | --- |
| 保持该项 | `{{item}}` | 不动（这就是默认值） |
| 追加 | `{{item}}, best quality` | 接在原文后面 |
| 前置 | `masterpiece, {{item}}` | 插在原文前面 |
| 覆盖 | `银发` | 整项替换 |
| 清空 | *（空框）* | 该项变成空字符串 |
| 后面的项不动 | 少写几个输入 | 没对应的项保持原值 |

文本类输入（文本框、每一行、连上的字符串）在合并前都会去掉首尾空白，所以两端的空格会丢；需要空格就写在占位符后面。从 `Create From Lists` 接进来的列表项则按原样使用。一个输入里可以写多个 `{{item}}`，每一处都会被替换。

一些具体的例子：

| 上游列表 | 输入 | 结果 |
| --- | --- | --- |
| `["one", "two", "three"]` | 每个框都写 `{{item}}` | 不变 |
| `["one", "two"]` | `{{item}}, masterpiece`、`best quality, {{item}}` | `["one, masterpiece", "best quality, two"]` |
| `["one", "two"]` | `red`、*(空)* | `["red", ""]` |
| `["one", "two", "three"]` | `A` | `["A", "two", "three"]` |
| `["one"]` | `a`、`b`、*(空)* | `["a", "b"]` |
| 无 | `{{item}}`、`{{item}}` | `["", ""]` |
| 无 | `cat`、`dog` | `["cat", "dog"]` |

## 案例走查：把一个角色拆成槽位

这就是示例工作流里的"衣柜"链条。六个槽位、五个阶段，一个阶段一个节点。

### 阶段 0 —— 纯注释骨架

一个 `Create From Strings (Multi)`，六个框，每个框只是说明这个槽位是干什么的：

```text
框 0  一个小技巧是，你可以在初始节点之前放一个纯注释节点来解释每一项。
      反正后面会被覆盖掉。
框 1  注释-服装
框 2  注释-表情
框 3  注释-动作（我们这里假设初始不写动作，后面有需要了再补充）
框 4  注释-镜头
框 5  注释-场景
```

这里的内容一条都不会留下来 —— 这正是它的用途。画布自己就把结构说明白了：即使下标 3 是空的，谁看图都知道那是动作槽。

### 阶段 1 —— 基础设定

再来一个 `Create From Strings (Multi)`，六个普通文本框，`prompt_list` 接阶段 0 的输出。普通文字等于覆盖，所以整个骨架被一次换掉：

```text
框 0  这是角色的头
框 1  角色的服装
框 2  角色的表情
框 3  （空）            ← 动作槽故意留空
框 4  镜头
框 5  场景
```

```text
列表 → ["这是角色的头", "角色的服装", "角色的表情", "", "镜头", "场景"]
```

### 阶段 2 —— 换装、换镜头

现在只给要变的槽位写框，而且列表有六项，这个节点只有五个框：

```text
保持    框 0  {{item}}
追加    框 1  {{item}}, 服装的基础上新增一些小细节, 或新增墨镜和帽子啥的
覆盖    框 2  把原来的表情删掉更换成表情2
保持    框 3  {{item}}                    ← 动作槽继续保持空
覆盖    框 4  镜头B
保持    没有槽 5 的框                      ← 场景原样保留
```

```text
列表 → ["这是角色的头",
        "角色的服装, 服装的基础上新增一些小细节, 或新增墨镜和帽子啥的",
        "把原来的表情删掉更换成表情2",
        "",
        "镜头B",
        "场景"]
```

"这项不动"有两种写法 —— 留个框写 `{{item}}`，或者干脆不写这个框 —— 这里正好都用上了：五个框，六项。

### 阶段 3 —— 不动一排框，只改一个槽

`Set Item`，索引 `4`，值 `再更换为镜头C`。只换镜头，别的都不碰。

```text
列表 → ["这是角色的头",
        "角色的服装, 服装的基础上新增一些小细节, 或新增墨镜和帽子啥的",
        "把原来的表情删掉更换成表情2",
        "",
        "再更换为镜头C",
        "场景"]
```

### 阶段 4 —— 拼回去

`Join To String`，分隔符用默认的 `", "`：

```text
这是角色的头, 角色的服装, 服装的基础上新增一些小细节, 或新增墨镜和帽子啥的, 把原来的表情删掉更换成表情2, , 再更换为镜头C, 场景
```

可以直接喂给文本编码器。注意中间那个 `, ,`：动作槽是空的，而 `Join To String` 是按原样拼接，不会跳过空项。

拼接放在最后是有意的 —— `Set Item` 输出的也是列表，而创建节点自带的 `joined_text` 只反映它自己那一次的输出，不含后续修改。

### 这样拆分的好处

- **一个阶段一个想法。**"基础角色""换套衣服""换个镜头"是三个独立节点，哪个都能单独静音、绕过、复制，不用重抄任何文字。
- **只写要变的槽。** `{{item}}` 和不写这个框都表示"不动"，所以一个阶段可以小到只有一行。
- **批量和单点都有。** 接上 `prompt_list` 的创建节点用一排框改很多槽位，`Set Item` 精准改一个。
- **列表是看得见的。** 随时插一个 `PromptList Show` 看 JSON，拼完后接一个内置的 `Preview Any` 看成品。

## 相关节点

- **`Join String Multi`**（KJNodes）把多个 `STRING` 输入收集成一个字符串，解决的是输入侧的问题；本插件的 `Join To String` 解决的是值侧的问题 —— 它拼接的那张列表，中间可以被任意多个节点改过。写这个节点时参考了它的实现。
- **`Preview Any`** 和 **`Primitive String`**（内置）是顺手的搭配：前者用来看单个输出，后者用来给 `Create From Upstream` 提供字符串。
- 开发思路参考：KJNodes (Join String Multi), ComfyUI-List-Utils, Kisekae

## 限制与注意

- 每个节点最多 100 个文本框/输入，索引最大 9999。这两个上限属于界面控件；`Show`、`Get Item`、`Set Item`、`Join To String` 本身能处理任意长度的列表。
- 列表里只有字符串。
- 目前没有"删除某一项"的节点 —— 要么重建列表，要么把不需要的槽位清空、接受那个重复的分隔符。
- 空项会作为空槽位参与拼接，所以 `["a", "", "b"]` 经 `Join To String` 会拼成 `a, , b`，经创建节点的 `joined_text` 则是 `a,,b`。
- 列表是一个值，因此不会触发"逐项执行"。要让一张图跑 N 次，得用计数器喂索引，或者用 ComfyUI 自带的列表节点。
- 目前节点的内嵌描述和 tooltip 只有中文。
